# AudioHub 1.0.0 · 真机验收清单

> 对应 `CONTINUE.md` 第十节的验收对照表。电脑端大部分逻辑已实测过；**手机端一项都没在真机上跑过**，所以下面标 ⚠️ 的都要你亲手确认。

## 一句话记住

- **日常使用**：电脑双击 `start-audiohub.bat`（一个），手机打开 App 配对听音。
- **验证 / 排查**：电脑双击 `audiohub-verify.bat`（一个），它自动跑完所有电脑端检查，并引导手机配合。
- 以前那一堆 `check-my-setup` / `show-key` / `probe-*` / `run-selftest` / `start-vban` 都已合并进上面两个文件，不用再单独找、单独点。

---

## 准备

1. **电脑**：解压 `AudioHub-PC-self-contained.zip`（推荐，零安装）或 `AudioHub-PC-framework-dependent.zip`（需先装 .NET 8 桌面运行时）到任意文件夹。
2. **手机**：安装 `app-debug.apk`（需允许"未知来源"）。
3. 手机和电脑连**同一个 Wi-Fi**。
4. 蓝牙耳机**先连到电脑**（不要连手机）。

---

## 日常使用（每次都这样，只点一个）

1. 电脑双击 `start-audiohub.bat` → 右下角托盘出现耳机图标（可能在 `^` 箭头里）。
2. 手机打开 AudioHub → 「查找电脑」→ 配对（或明文直连）→「开始发送」。
3. 戴蓝牙耳机：**电脑自己的声音 + 手机的声音同时从耳机出来**。

> 日常就是这一件事。验证 / 排查才用到下面那个脚本。

---

## 一键验证 / 排查（`audiohub-verify.bat`，只点一个）

双击它，按屏幕提示走：

- **自动完成**（不需手机）：显示本机 IP、检查并修复防火墙规则、列出播放设备、显示配对钥匙、列出手机端要填的参数。
- **引导完成**（需手机）：在手机上配对并开始发送后，它自动验证「发现」和「加密链路」是否通过，并给出 PASS / FAIL。
- ⚠️ 验证时**不要**同时开 `start-audiohub.bat`——两者都要占 UDP 6980 端口，会冲突。
- 验证完日常用，关掉它，双击 `start-audiohub.bat` 即可。

> 这个脚本覆盖了原清单里 A1/A3/A4、C 段的电脑端部分，以及发现 / 加密链路的客观验证；B（手机界面）、D（听感）、E（记忆）、F（边界）仍需你亲手判断，见下表。

**判据提醒（最容易"听起来正常"却其实没加密）：**
- 手机「链路」那一行必须显示「**已加密（AES-256-GCM）**」才算配对生效。
- 显示「明文，未加密」但声音照响——这是最危险的情况，别放过。

> 主观听感（延迟 / 爆音 / 啸叫 / 音量）只能你判断。`audiohub-verify.bat` 只能证明"包到了且解开了"，代替不了耳朵。

## 已知坑（失败时先看这里）

- **"查找电脑"找不到**：最常见是路由器开了 **AP 隔离 / 客户端隔离**，或防火墙挡了 6979。先跑 `audiohub-verify.bat`（它会检查 / 修复防火墙）；仍不行就在手机手填电脑 IP（用 verify 第一步显示的 IPv4）。
- **声音不来、两边都不报错**：多半是加密没对上（密钥错 / 身份 UUID 错 / 两端版本不一致），去手机看「链路」那行。
- **电脑生成过新密钥**（删了 `%LOCALAPPDATA%\AudioHub\key.json`）：手机还记着旧密钥，会**静默连不上**，手机端没有任何提示。绕法：清除手机应用数据，重新配对。
- **端口冲突**：6980 被占时验证会失败，先关掉托盘应用（`start-audiohub.bat`）再跑 `audiohub-verify.bat`。
